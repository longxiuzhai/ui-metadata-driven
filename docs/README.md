# 项目文档索引

这里的文档按“事实说明、开发操作、设计背景”分层。开发时优先相信源码、测试和本目录中的当前实现文档；仓库根目录的两份方案文档记录设计演进，不保证所有内容都已经落地。

## 新人阅读路径

1. [项目 README](../README.md)：了解目标、技术栈并启动项目；
2. [开发指南](开发指南.md)：掌握目录、调试、测试和常见开发任务；
3. [架构说明](架构说明.md)：理解后端装配、前端运行时和模块边界；
4. [API 参考](API参考.md)：联调时查询接口、请求头和数据协议；
5. 根据需求阅读[扩展卡片开发指南](扩展卡片开发指南.md)或[页面动作与编辑能力设计方案](页面动作与编辑能力设计方案.md)。
6. 账号、角色、权限或菜单开发参见[账号与权限开发指南](账号与权限开发指南.md)。

## 文档维护规则

- 命令应注明执行目录，并尽量在提交前真实运行；
- API 只记录当前代码中实际存在的映射；规划中接口必须明确标注“未实现”；
- 示例优先引用仓库中已有的纵向链路，避免维护一套脱离代码的伪实现；
- 新增组件、动作类型、路由或表单编码时，同时更新对应注册表、后端校验白名单和文档；
- 已知失败不能写成“全部通过”，应记录失败数量、原因和修复入口。
