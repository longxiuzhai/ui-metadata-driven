# 开发指南

本文面向第一次接手项目的开发者，覆盖本地环境、源码入口、开发流程、测试和已知问题。

## 1. 环境准备

最低要求：

- JDK 11；
- Maven 3.6+；
- Node.js（建议使用当前维护中的 LTS 版本）；
- npm，依赖安装使用仓库中的 `package-lock.json`。

当前项目没有数据库、缓存、消息队列和环境变量依赖，演示数据存放在后端内存仓库中。端口约定：后端 `8080`，Vite 开发服务器 `5173`。

检查环境：

```bash
java -version
mvn -version
node --version
npm --version
```

## 2. 首次启动

后端模块相互依赖，先从 `backend` 安装整个 reactor：

```bash
cd backend
mvn install
cd application
mvn spring-boot:run
```

前端另开终端：

```bash
cd frontend
npm ci
npm run dev
```

快速检查：

```bash
curl 'http://localhost:8080/api/ui/pages/home/cards'
curl 'http://localhost:8080/api/ui/pages/customer_detail/cards?customerId=1001'
curl 'http://localhost:8080/api/accounts/me'
```

如果前端页面提示元数据加载失败，先直接请求后端接口，再检查 `frontend/vite.config.ts` 中的代理地址和两个进程的端口。

## 4. 源码与生成文件

前端应修改 `.ts` 和 `.vue` 源文件。仓库当前还跟踪了同目录下的 `.js`、`.vue.js` 和 `tsconfig.app.tsbuildinfo`，它们由 `vue-tsc -b` 生成，不应手工编辑。

这是当前的技术债：`tsconfig.app.json` 未设置 `noEmit`，执行 `npm run build` 可能在 `src` 下产生或更新 JavaScript 文件（例如新增测试对应的 `.test.js`）。提交前务必检查 `git status`，不要把无意产生的构建文件混入业务改动；长期建议改为类型检查不落盘，并统一清理已跟踪产物。

后端 `target/`、前端 `node_modules/` 和 `dist/` 已被 `.gitignore` 忽略。

## 5. 日常开发流程

### 5.1 只改后端卡片定义

1. 在 `tenant-customization` 新增或修改 `CardProvider`；
2. 确认 `pageCode/cardCode`，设置启动期和请求期条件；
3. 复用现有组件时，确保 `props` 与组件消费的数据结构一致；
4. 为统一元数据接口补充 MockMvc 测试；
5. 执行后端测试，并用 `curl` 检查实际响应。

详细模板见[扩展卡片开发指南](扩展卡片开发指南.md)。

### 5.2 新增一种前端卡片组件

这是一项前后端联动修改：

1. 在 `frontend/src/components/cards/` 新增 Vue 组件；
2. 在 `frontend/src/cardRegistry.ts` 注册稳定的组件编码；
3. 在后端 `CardDefinitionValidator.COMPONENTS` 增加同一编码；
4. 增加组件测试或至少覆盖空数据、错误数据和正常数据；
5. 新增 Provider 示例并验证响应式宽度、加载和失败状态。

仅修改前端注册表会被后端校验拒绝；仅修改后端白名单会在前端落入 `UnknownCard`。

### 5.3 新增业务页面并使用卡片

下面以“订单详情页”为例，从后端到前端新增一个真正可访问的页面。完成后访问：

```text
http://localhost:5173/order-detail?orderId=O-1001
```

页面编码先统一，后续所有文件必须使用同一组值：

| 用途 | 示例值 | 出现位置 |
|---|---|---|
| 页面编码 | `order_detail` | Provider、元数据 API、前端 `pageCode` |
| 卡片编码 | `order_basic` | Provider、刷新目标、Action 上下文 |
| 路由名称 | `order-detail` | Vue Router |
| 页面上下文参数 | `orderId` | URL 查询参数、`pageContext`、`dataApi` 占位符 |
| 组件编码 | `KeyValueCard` | Provider；该组件已在前后端白名单注册 |

#### 第 2 步：新增后端 CardProvider

在同一目录新建 `OrderBasicCardProvider.java`。Provider 只描述卡片，不在 `definition()` 中查询订单数据。

```java
package com.example.metadataui.customization.demo;

import com.example.metadataui.card.condition.CardConditional;
import com.example.metadataui.card.context.CardRequestContext;
import com.example.metadataui.card.model.CardDefinition;
import com.example.metadataui.card.model.ResponsiveSpan;
import com.example.metadataui.card.spi.CardProvider;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Map;

@Component
@ConditionalOnProperty(
        name = "metadata.cards.order-basic.enabled",
        havingValue = "true",
        matchIfMissing = true)
@CardConditional(permissions = "order:read")
public class OrderBasicCardProvider implements CardProvider {
    @Override
    public String pageCode() {
        return "order_detail";
    }

    @Override
    public String cardCode() {
        return "order_basic";
    }

    @Override
    public CardDefinition definition(CardRequestContext context) {
        return new CardDefinition(
                cardCode(), "订单信息", "KeyValueCard", 10,
                new ResponsiveSpan(24, 24, 12),
                "/api/orders/{orderId}/basic", "eager", "order:read",
                Map.of("columns", 2, "fields", List.of(
                        Map.of("key", "orderNo", "label", "订单号"),
                        Map.of("key", "contactName", "label", "联系人"),
                        Map.of("key", "status", "label", "状态"))),
                List.of());
    }
}
```

`DemoTenantAutoConfiguration` 已扫描该包，带 `@Component` 的 Provider 和 Controller 会自动注册，不需要再修改 Spring 配置。验证元数据：

```bash
curl 'http://localhost:8080/api/ui/pages/order_detail/cards?orderId=O-1001'
```

响应中应出现 `pageCode=order_detail`、`cards[0].code=order_basic`，且 `dataApi` 仍保留 `{orderId}`，由前端使用页面上下文替换。

#### 第 6 步：让 App.vue 识别新页面

当前项目不是通用页面工厂，`App.vue` 对页面有显式分支，因此需要完成以下修改。

先导入 API 并扩展页面类型：

```ts
import { getCustomerDetailCards, getHomeCards, getOrderDetailCards } from './api'

type PageKind = 'home' | 'customer' | 'orders' | 'orderDetail'
```

在 `activePage` 中识别路由，并读取 `orderId`：

```ts
const activePage = computed<PageKind>(() => {
  if (route.name === 'customer-detail') return 'customer'
  if (route.name === 'order-list') return 'orders'
  if (route.name === 'order-detail') return 'orderDetail'
  return 'home'
})

const orderId = computed(() => String(route.query.orderId ?? 'O-1001'))
```

把 `pageCode` 改为明确分支，避免继续叠加三元表达式：

```ts
const pageCode = computed(() => {
  if (activePage.value === 'customer') return 'customer_detail'
  if (activePage.value === 'orderDetail') return 'order_detail'
  return 'home'
})
```

把 `pageContext` 改成下面的完整分支。键名必须与 Provider 的 `{orderId}` 完全一致：

```ts
const pageContext = computed<Record<string, string>>(() => {
  if (activePage.value === 'orderDetail') {
    return { orderId: orderId.value }
  }
  if (activePage.value === 'customer') {
    return { customerId: customerId.value }
  }
  if (activePage.value === 'orders') {
    return Object.fromEntries(
      Object.entries(route.query).map(([key, value]) => [key, String(value ?? '')])
    )
  }
  return { userId: userId.value }
})
```

在 `heading/subtitle/avatar` 中增加 `orderDetail` 的显示文案：

```ts
const heading = computed(() => {
  if (activePage.value === 'customer') return '客户详情'
  if (activePage.value === 'orders') return '客户订单'
  if (activePage.value === 'orderDetail') return '订单详情'
  return '工作首页'
})

const subtitle = computed(() => {
  if (activePage.value === 'orderDetail') {
    return `订单编号 ${orderId.value} · 页面卡片由后端动态装配`
  }
  // 保留现有 customer、orders、home 返回逻辑
})

const avatar = computed(() => {
  if (activePage.value === 'orderDetail') return 'OD'
  // 保留现有 customer、orders、home 返回逻辑
})
```

上面 `subtitle/avatar` 中的注释代表把该分支插入现有 computed，不要删除原有分支。随后修改 `loadPage()` 的请求分支：

```ts
page.value =
  activePage.value === 'customer'
    ? await getCustomerDetailCards(customerId.value)
    : activePage.value === 'orderDetail'
      ? await getOrderDetailCards(orderId.value)
      : await getHomeCards()
```

现有模板的 `v-else-if="page"` 会自动使用 `DynamicCard` 渲染新页面，不需要复制一套卡片循环。若要在顶部导航显示入口，再增加一个调用 `router.push({ name: 'order-detail', query: { orderId: orderId.value } })` 的按钮。

### 5.4 给卡片新增编辑动作

下面继续给上一节的 `order_basic` 卡片增加“编辑订单”动作。标准链路由项目现有的 `ActionRuntime`、`FormDrawer` 和统一 Action API 负责，新业务只需要提供四部分：卡片动作元数据、后端 Handler、前端表单、注册表映射。

先统一编码：

| 用途 | 示例值 |
|---|---|
| 卡片动作编码 | `edit`，只需在当前卡片内唯一 |
| 表单编码 | `order_basic_edit` |
| 后端动作编码 | `order.basic.update`，全局唯一 |
| 权限编码 | `order:update` |
| 成功后刷新卡片 | `order_basic` |

#### 第 1 步：准备可更新的业务 Repository

Handler 不应把业务数据直接存在自身。为了让示例可以运行，在 `backend/tenant-customization/src/main/java/com/example/metadataui/customization/demo/` 新建 `DemoOrderRepository.java`：

```java
package com.example.metadataui.customization.demo;

import com.example.metadataui.action.exception.ActionConflictException;
import org.springframework.stereotype.Repository;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Repository
public class DemoOrderRepository {
    private final Map<String, OrderSnapshot> orders = new ConcurrentHashMap<>();

    public OrderSnapshot get(String orderId) {
        return orders.computeIfAbsent(orderId,
                id -> new OrderSnapshot(id, "张三", "CREATED", 1));
    }

    public synchronized OrderSnapshot update(
            String orderId,
            long expectedVersion,
            String contactName,
            String status) {
        OrderSnapshot current = get(orderId);
        if (current.getVersion() != expectedVersion) {
            throw new ActionConflictException("订单已被其他操作修改，请重新加载");
        }
        OrderSnapshot updated = new OrderSnapshot(
                orderId, contactName, status, current.getVersion() + 1);
        orders.put(orderId, updated);
        return updated;
    }

    public static final class OrderSnapshot {
        private final String orderNo;
        private final String contactName;
        private final String status;
        private final long version;

        public OrderSnapshot(
                String orderNo,
                String contactName,
                String status,
                long version) {
            this.orderNo = orderNo;
            this.contactName = contactName;
            this.status = status;
            this.version = version;
        }

        public long getVersion() {
            return version;
        }

        public Map<String, Object> values() {
            return Map.of(
                    "orderNo", orderNo,
                    "contactName", contactName,
                    "status", status);
        }
    }
}
```

然后把上一节的 `OrderDetailDataController` 改为读取该仓库，确保编辑后刷新卡片能看到新值：

```java

    this.repository = repository;

    // 生产环境先校验当前账号对 orderId 的实体数据权限。
    return repository.get(orderId).values();
}
```

这是可运行的内存演示实现。生产项目应由订单领域 Service 操作数据库，并使用数据库乐观锁和事务。

#### 第 3 步：实现后端 UiActionHandler

在 `backend/tenant-customization/src/main/java/com/example/metadataui/customization/demo/action/` 新建 `OrderBasicEditActionHandler.java`：

```java
package com.example.metadataui.customization.demo.action;

import com.example.metadataui.action.model.ActionCommand;
import com.example.metadataui.action.model.ActionContext;
import com.example.metadataui.action.model.ActionPreparation;
import com.example.metadataui.action.model.ActionResult;
import com.example.metadataui.action.spi.UiActionHandler;
import com.example.metadataui.customization.demo.DemoOrderRepository;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Component
public class OrderBasicEditActionHandler implements UiActionHandler {
    private static final String FORM_CODE = "order_basic_edit";
    private final DemoOrderRepository repository;
    private final Map<String, ActionResult> completedRequests = new ConcurrentHashMap<>();

    public OrderBasicEditActionHandler(DemoOrderRepository repository) {
        this.repository = repository;
    }

    @Override
    public String actionCode() {
        return "order.basic.update";
    }

    @Override
    public String permission() {
        return "order:update";
    }

    @Override
    public boolean supports(ActionContext context) {
        return "order_detail".equals(context.getPageCode())
                && "order_basic".equals(context.getCardCode());
    }

    @Override
    public ActionPreparation prepare(ActionContext context) {
        String orderId = context.requiredParam("orderId");
        DemoOrderRepository.OrderSnapshot order = repository.get(orderId);
        // 在真实项目中，这里还要校验当前租户和用户对该订单的数据权限。
        return new ActionPreparation(FORM_CODE, order.values(), order.getVersion());
    }

    @Override
    public ActionResult execute(ActionContext context, ActionCommand command) {
        String idempotencyKey = context.getTenantId()
                + ":" + context.getUserId()
                + ":" + command.getRequestId();
        ActionResult completed = completedRequests.get(idempotencyKey);
        if (completed != null) {
            return completed;
        }

        String orderId = context.requiredParam("orderId");
        String contactName = requiredString(command.getValues(), "contactName");
        String status = requiredString(command.getValues(), "status");
        if (!List.of("CREATED", "CONFIRMED", "CLOSED").contains(status)) {
            throw new IllegalArgumentException("unsupported order status");
        }

        // update 内必须检查 expectedVersion，并完成实体数据权限和业务校验。
        repository.update(orderId, command.getVersion(), contactName, status);
        ActionResult result = new ActionResult("订单已保存", List.of("order_basic"));
        completedRequests.put(idempotencyKey, result);
        return result;
    }

    private String requiredString(Map<String, Object> values, String name) {
        Object value = values.get(name);
        if (!(value instanceof String) || ((String) value).isBlank()) {
            throw new IllegalArgumentException(name + " is required");
        }
        return (String) value;
    }
}
```

带 `@Component` 的 Handler 会被 `UiActionHandlerRegistry` 自动发现；若 `actionCode()` 重复，应用会在启动时失败。

为了在本地使用默认演示账号看到“编辑订单”按钮，还要在 `backend/application/src/main/java/com/example/account/AccountService.java` 的 `DEMO_PERMISSIONS` 中加入 `order:update`：

```java
private static final Set<String> DEMO_PERMISSIONS = Set.of(
        "home:read", "home:activity:read", "customer:read", "customer:update",
        "customer:tag:read", "customer:trace:read", "order:read", "order:update");
```

这里只是演示账号配置。生产环境应从认证和授权系统加载权限，不能在代码中写死。

除了统一权限检查，Handler 仍必须负责：

- 根据 `tenantId/userId/orderId` 做实体数据权限校验；
- 只读取允许修改的字段，不能把 `values` 整体反序列化后直接覆盖实体；
- 校验状态枚举和业务状态流转；
- 使用 `command.version` 做乐观锁；
- 使用 `command.requestId` 做持久化幂等。现有客户示例只使用进程内 Map，不适合多实例生产环境。

#### 第 4 步：新增前端表单组件

在 `frontend/src/forms/OrderBasicEditForm.vue` 新建表单。标准表单组件接收 `modelValue`，每次字段变化都发出新的完整对象：

```vue
<script setup lang="ts">
const props = defineProps<{ modelValue: Record<string, unknown> }>()
const emit = defineEmits<{
  'update:modelValue': [value: Record<string, unknown>]
}>()

function update(key: string, value: string) {
  emit('update:modelValue', { ...props.modelValue, [key]: value })
}
</script>

<template>
  <div class="form-grid">
    <label>
      <span>联系人</span>
      <input
        :value="String(modelValue.contactName ?? '')"
        @input="update('contactName', ($event.target as HTMLInputElement).value)"
      />
    </label>

    <label>
      <span>状态</span>
      <select
        :value="String(modelValue.status ?? 'CREATED')"
        @change="update('status', ($event.target as HTMLSelectElement).value)"
      >
        <option value="CREATED">已创建</option>
        <option value="CONFIRMED">已确认</option>
        <option value="CLOSED">已关闭</option>
      </select>
    </label>
  </div>
</template>
```

输入值只做前端体验校验，不能代替 Handler 的服务端校验。可以复用 `CustomerBasicEditForm.vue` 的样式。

#### 第 5 步：注册表单白名单

修改 `frontend/src/actions/formRegistry.ts`：

```ts
import OrderBasicEditForm from '../forms/OrderBasicEditForm.vue'

export const formRegistry: Record<string, Component> = {
  customer_basic_edit: CustomerBasicEditForm,
  order_basic_edit: OrderBasicEditForm
}
```

`order_basic_edit` 必须与 Provider 的 `ActionTarget.form(...)` 以及 Handler 返回的 `ActionPreparation.formCode` 完全一致。若未注册，`FormDrawer` 会显示“未注册的表单”。

使用现有标准抽屉时，不需要修改以下文件：

- `ActionRuntime.ts`：负责解析 `orderId` 并发出打开表单请求；
- `api.ts`：已有通用 prepare/execute 请求；
- `FormDrawer.vue`：负责加载初始值、提交版本号和 `requestId`、关闭抽屉；
- `App.vue`：收到 `ActionResult.refreshCards` 后更新卡片刷新令牌。

只有新增动作类型或新的展示容器时，才应修改这些平台文件。

#### 第 6 步：补后端动作测试

在 `application` 模块增加集成测试，至少覆盖准备、成功修改、旧版本冲突和无权限直调。结构可参考 `UiActionControllerTest`：

```java
mvc.perform(post("/api/ui/actions/order.basic.update/prepare")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"pageCode\":\"order_detail\","
                        + "\"cardCode\":\"order_basic\","
                        + "\"params\":{\"orderId\":\"O-1001\"}}"))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.formCode").value("order_basic_edit"))
        .andExpect(jsonPath("$.version").isNumber());
```

执行接口请求体必须包含：

```json
{
  "pageCode": "order_detail",
  "cardCode": "order_basic",
  "params": { "orderId": "O-1001" },
  "values": { "contactName": "李四", "status": "CONFIRMED" },
  "version": 1,
  "requestId": "order-update-test-1"
}
```

无权限用例添加请求头 `X-Permissions: order:read`，直接调用 execute 应返回 `403`；使用旧 version 再提交应返回 `409`；重复使用同一 `requestId` 时应返回第一次结果或明确的幂等冲突。

## 8. 编码约定

- `pageCode`、`cardCode`、`actionCode`、组件编码一旦发布应保持稳定；
- 同一页面内 `cardCode` 唯一，注册器会在启动时拒绝重复项；
- Provider 只描述元数据，不查询卡片主体数据；
- `supports(context)` 只做轻量判断，不执行 SQL 或远程调用；
- `dataApi` 只能使用站内 `/api/` 路径，路径变量来自页面上下文；
- 元数据负责“展示什么”，数据接口和 Action Handler 仍负责真实鉴权；
- 不在元数据中下发 HTML、JavaScript、CSS、SpEL、任意 URL 或外部组件地址。

## 9. 已知问题与技术债

### 前端编译产物进入源码目录

见“源码与生成文件”。这会增加误改和提交噪声，也可能让无扩展名 import 的解析变得难以判断。建议后续单独提交一次清理：设置 TypeScript `noEmit`、删除已跟踪编译产物、补充忽略规则并重新验证构建。

### 演示实现不等于生产实现

当前账号、权限、Feature、客户数据和幂等记录都在内存中；数据接口未做实体级鉴权；没有持久化、审计存储、限流和分布式幂等。生产接入检查见[架构说明](架构说明.md#生产化边界)。
