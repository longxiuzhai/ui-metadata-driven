# 扩展卡片开发指南

## 扩展边界

新增卡片分为两类：

- 复用 `KeyValueCard`、`TagGroupCard`、`TimelineCard`：只新增后端 Provider，客户详情页不改代码；
- 新交互形态：先在前端实现组件并加入 `cardRegistry`，同时加入后端白名单，再新增 Provider。

插件只描述卡片，不返回 JSON 字符串、Vue 模板、JavaScript、HTML、CSS 或外部 URL。

## Provider 模板

建议每个业务扩展建立独立 Maven JAR，只依赖 `customer-detail-contract`。Provider 与它对应的数据 Controller/Service 放在同一插件模块中；主应用只在 `application/pom.xml` 声明是否装配该插件。

```java
@Component
@ConditionalOnProperty(
    name = "modules.customer-score.enabled",
    havingValue = "true",
    matchIfMissing = true
)
@CardConditional(
    feature = "customerScore",
    permissions = "customer:score:read"
)
public class CustomerScoreCardProvider implements CustomerDetailCardProvider {

    @Override
    public String cardCode() {
        return "customer_score";
    }

    @Override
    public boolean supports(CardContext context) {
        // 只放无法由通用 Condition 表达的业务判断。
        return !"anonymous".equals(context.getUserId());
    }

    @Override
    public CardDefinition definition(CardContext context) {
        return new CardDefinition(
            cardCode(), "客户评分", "KeyValueCard", 30,
            new ResponsiveSpan(24, 12, 8),
            "/api/customers/{customerId}/score", "on-visible",
            "customer:score:read",
            Map.of("columns", 1, "fields", List.of(
                Map.of("key", "score", "label", "综合评分")
            )),
            List.of()
        );
    }
}
```

## 三层条件的职责

| 层次 | 执行时机 | 适合判断 | 示例 |
|---|---|---|---|
| Spring Boot Condition | 应用启动 | 模块/JAR/配置是否存在 | `@ConditionalOnProperty`、`@ConditionalOnClass` |
| `@CardConditional` | 每次聚合请求 | 通用上下文规则 | 权限、租户、Feature Flag |
| `supports` | 每次聚合请求 | Provider 专属业务规则 | 客户类型、数据状态、套餐额度 |

不要在 `supports` 中执行慢 SQL 或远程调用。需要批量业务状态时，应先构造包含所需状态的 `CardContext`，避免每个 Provider 产生一次 I/O。

## 生产环境接入

演示工程使用请求头生成用户上下文。生产环境应：

1. 从 Spring Security `Authentication` 获取租户、用户和权限，忽略客户端伪造的权限头；
2. 元数据聚合结果只能决定“是否展示”，数据 API 与动作 API 必须重新鉴权；
3. 缓存键至少包含协议版本、租户、权限集合摘要和 Feature Flag 版本；
4. Provider 异常应记录 `cardCode`，根据业务选择跳过故障卡片或令聚合失败；
5. 发布时校验后端组件白名单与前端 `cardRegistry` 一致。

协议的机器可读约束见 `backend/customer-detail-contract/src/main/resources/schema/customer-detail-card-v1.schema.json`。
