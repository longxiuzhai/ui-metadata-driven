# 页面动作与编辑能力设计方案

## 1. 目标

在现有卡片级元数据展示能力上增加受控交互，第一阶段支持：

- 刷新当前或指定卡片；
- 使用页面上下文、卡片数据、账号信息和常量作为动态参数跳转站内页面；
- 打开已注册 Vue 表单，在抽屉中完成加载、校验和保存；
- 通过后端 Action SPI 执行业务修改；
- 保存成功后定向刷新相关卡片。

本阶段不支持 JavaScript、SpEL、任意 URL、远程组件和任意表单 DSL。

## 2. 设计原则

1. 元数据只描述意图，不携带执行代码；
2. 路由、表单、动作类型和后端命令全部使用白名单注册编码；
3. 前端权限只控制展示，后端 Handler 必须重新鉴权；
4. 展示 SPI 和动作 SPI 使用相同的注册、条件启停和冲突校验方式；
5. 第一阶段使用已注册 Vue 表单，表单稳定后再评估受限 SchemaForm；
6. 保留原有 `target` 字符串协议的读取兼容性。

## 3. 总体架构

```text
CardAction 元数据
  → ActionRuntime
  → ParameterResolver
  → ActionExecutorRegistry
      ├─ refresh → CardRefreshBus
      ├─ navigate → routeRegistry / Vue Router
      └─ open-form → formRegistry / FormDrawer
                         ↓
                  统一 Action API
                         ↓
                UiActionHandlerRegistry
                         ↓
                 UiActionHandler SPI
```

后端继续保持三层：

| 模块 | 职责 |
|---|---|
| `card-platform` | 动作模型、参数绑定、校验、`UiActionHandler` SPI |
| `application` | 统一 prepare/execute 接口、账号与权限上下文、Handler 注册 |
| `tenant-customization` | 具体表单准备、业务校验、保存和结果定义 |

## 4. 动作协议

### 4.1 参数绑定

```json
{
  "source": "page-context",
  "path": "customerId",
  "required": true
}
```

允许的来源：

- `page-context`：页面路由和业务上下文；
- `card-data`：当前卡片已经加载的数据；
- `account`：当前账号的非敏感属性；
- `literal`：元数据中的常量。

`path` 只允许字母、数字、下划线和点号组成的字段路径，禁止原型链特殊字段。

### 4.2 动态跳转

```json
{
  "code": "view_customer_orders",
  "label": "查看订单",
  "type": "navigate",
  "target": {
    "routeCode": "order_list"
  },
  "params": {
    "customerId": {
      "source": "page-context",
      "path": "customerId",
      "required": true
    },
    "status": {
      "source": "literal",
      "value": "OPEN"
    }
  }
}
```

前端通过 `routeRegistry` 把 `routeCode` 转换为 Vue Router 的命名路由，不接受任意跳转 URL。

### 4.3 编辑动作

```json
{
  "code": "edit_customer_basic",
  "label": "编辑",
  "type": "open-form",
  "permission": "customer:update",
  "target": {
    "formCode": "customer_basic_edit",
    "actionCode": "customer.basic.update",
    "presentation": "drawer"
  },
  "params": {
    "customerId": {
      "source": "page-context",
      "path": "customerId",
      "required": true
    }
  },
  "success": {
    "message": "客户信息已保存",
    "close": true,
    "refreshCards": ["basic_info"]
  }
}
```

## 5. 后端 API

### 5.1 准备表单

```http
POST /api/ui/actions/{actionCode}/prepare
```

请求包含 `pageCode`、`cardCode` 和解析后的业务参数。响应包含 `formCode`、初始值和版本号。

### 5.2 执行动作

```http
POST /api/ui/actions/{actionCode}/execute
```

请求包含业务参数、表单值、版本号和 `requestId`。后端使用版本号执行乐观锁检查，使用 `requestId` 防止重复提交。

## 6. Action SPI

```java
public interface UiActionHandler {
    String actionCode();
    String permission();
    ActionPreparation prepare(ActionContext context);
    ActionResult execute(ActionContext context, ActionCommand command);
}
```

核心应用负责：

- 查找 Handler；
- 校验动作权限；
- 注入可信账号和租户；
- 转换统一异常；
- 记录动作编码、用户、租户、耗时和结果。

定制 Handler 负责：

- 实体数据权限；
- 输入白名单和业务校验；
- 乐观锁；
- 持久化和业务审计。

## 7. 前端运行时

`DynamicCard` 只负责呈现按钮并发出动作事件。页面级 `ActionRuntime` 统一处理动作，避免每张卡片自行实现跳转、表单和提示。

```text
frontend/src/actions/
├── ActionRuntime.ts
├── ParameterResolver.ts
├── routeRegistry.ts
├── formRegistry.ts
└── executors/
```

表单组件接收初始值、版本号、提交状态和字段错误。动作成功后通过刷新总线更新指定卡片，不重新加载整个页面。

## 8. 安全边界

- execute 接口必须重新校验账号权限和实体数据权限；
- 不允许元数据指定任意提交地址；
- Handler 只能绑定白名单字段；
- 参数数量、字符串长度和对象深度必须限制；
- 版本冲突返回 `409`；
- 重复 `requestId` 返回第一次执行结果或明确冲突；
- 路由、表单、组件、动作类型均使用注册表白名单；
- 所有修改动作记录操作人、租户、实体、结果和耗时。

## 9. 分阶段实施

1. 动作协议、参数解析、路由和执行器；
2. 客户基本信息编辑纵向链路；
3. 字段级错误、二次确认、删除和批量动作；
4. 在表单模型稳定后评估受限 SchemaForm。

## 10. 验收标准

1. 动态参数能从页面上下文正确传入命名路由；
2. 未注册路由、表单或动作编码会被拒绝；
3. 无权限用户既看不到动作，也无法直接调用 execute；
4. 表单能加载初始值并提交修改；
5. 旧版本号提交返回冲突；
6. 保存成功后只刷新配置的卡片；
7. 单个动作失败不影响页面和其他卡片。
