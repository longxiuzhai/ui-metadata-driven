# 账号与权限开发指南

## 1. 已实现能力

- 用户名密码注册、登录和 BCrypt 密码存储；
- HMAC-SHA256 JWT Bearer Token，无服务端 Session；
- 用户启停与用户角色分配；
- 角色 CRUD，以及角色与权限、菜单的多对多配置；
- 权限和菜单 CRUD；
- 登录用户按角色和权限加载动态菜单；
- 卡片元数据和 Action 继续复用同一权限集合；
- MySQL 持久化、Flyway 建表、H2 集成测试。

Redis当前不是运行必需项。JWT每次请求从数据库加载权限，因此角色变更立即生效。用户量增大后，可用 Redis 缓存 `userId → roles/permissions/menus`，并在管理操作后按用户或角色精确失效；也可保存 JWT `jti` 撤销列表实现服务端强制退出。

## 2. 本地启动

```bash
docker compose up -d mysql

cd backend
mvn install
cd application
mvn spring-boot:run
```

默认连接：

| 配置 | 默认值 | 环境变量 |
|---|---|---|
| JDBC URL | `jdbc:mysql://localhost:3306/metadata_ui...` | `DB_URL` |
| 用户名 | `metadata_ui` | `DB_USERNAME` |
| 密码 | `metadata_ui` | `DB_PASSWORD` |
| JWT 密钥 | 仅适合本地的默认值 | `JWT_SECRET` |
| Token 有效期 | 28800 秒 | `JWT_TTL_SECONDS` |
| 初始管理员 | `admin / Admin123!` | `BOOTSTRAP_ADMIN_USERNAME/PASSWORD` |

生产环境必须替换 JWT 密钥和初始管理员密码，并在初始化完成后关闭或限制 bootstrap。

## 3. 数据模型

```text
sys_user ──< sys_user_role >── sys_role
                                  ├──< sys_role_permission >── sys_permission
                                  └──< sys_role_menu >──────── sys_menu
```

Flyway迁移位于 `backend/application/src/main/resources/db/migration/`。不要直接修改已经发布到环境中的迁移；后续变更应新增 `V2__*.sql`。

## 4. 认证链路

```text
POST /api/auth/login
  → 校验 BCrypt 密码和账号状态
  → 签发仅包含 uid/tenant/username/iat/exp 的 JWT
  → 前端保存 Token
  → 请求携带 Authorization: Bearer <token>
  → JwtAuthenticationFilter 校验签名和过期时间
  → 从数据库加载最新角色、权限
  → 写入 Spring SecurityContext
```

JWT不直接携带权限，避免角色调整后旧 Token 持续拥有旧权限。`@PreAuthorize` 保护管理接口，卡片平台通过 `CardRequestContextFactory` 使用同一账号权限集合。

## 5. 核心接口

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/api/auth/register` | 公开 |
| POST | `/api/auth/login` | 公开 |
| POST | `/api/auth/logout` | 已登录；当前为客户端删除 Token |
| GET | `/api/accounts/me` | 已登录 |
| GET | `/api/menus/me` | 已登录 |
| GET/PUT | `/api/admin/users/**` | `system:user:manage` |
| GET/POST/PUT/DELETE | `/api/admin/roles/**` | `system:role:manage` |
| GET/POST/PUT/DELETE | `/api/admin/permissions/**` | `system:permission:manage`；角色页可读取 |
| GET/POST/PUT/DELETE | `/api/admin/menus/**` | `system:menu:manage`；角色页可读取 |

## 6. 新增业务权限

1. 约定稳定编码，例如 `order:approve`；
2. 在权限管理页面创建权限，资源填 `order`，动作填 `approve`；
3. 在角色页面把权限分配给目标角色；
4. 后端接口使用 `@PreAuthorize("hasAuthority('order:approve')")`；
5. 卡片或动作使用同一 `permission` 编码；
6. 如需菜单入口，在菜单配置中填写 `permissionCode=order:approve`，再把菜单分配给角色；
7. 覆盖有权限和无权限测试。

前端隐藏按钮只改善体验，后端接口必须重新鉴权。

## 8. 生产化检查

- JWT密钥使用密钥管理服务注入，不提交仓库；
- 登录增加速率限制、失败计数、验证码或 MFA；
- 注册增加邮箱/手机号验证和租户邀请机制；
- 管理操作记录操作者、变更前后值、时间和来源 IP；
- 禁止管理员停用或移除自己的最后一个管理员角色；
- 引入 Redis 时设置短 TTL、缓存穿透保护和可靠失效；
- Token需要强制撤销时加入 `jti` 和 Redis denylist；
- 多租户场景给角色、菜单、权限增加租户或模板归属，并在所有查询中强制租户条件；
- 数据库账号遵循最小权限，开启备份和迁移回滚预案。
